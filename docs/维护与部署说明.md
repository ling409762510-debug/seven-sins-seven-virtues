# 维护与部署说明

## 1. 文件分工

| 文件 | 内容 |
| --- | --- |
| config.js | 产品名称、统一测试码、存储版本 |
| content.js | 30 题的组卷方式、维度定义、三档解释、建议、触发标签 |
| scoring.js | 计分、并列处理、报告组合 |
| storage.js | 浏览器记录读取、校验与保存 |
| app.js | 入口、说明、答题、报告、分段图片导出 |
| styles.css / visuals.js | 黑金酒红样式、主题几何图与雷达 |
| .github/workflows/deploy.yml | 自动测试、构建与发布 |

源码维护在根目录；`dist` 由构建生成，不直接修改。

`npm run build` 同时生成 `dist/standalone.html`，它内嵌样式、脚本和图片导出依赖，便于离线演示。请从源码修改后重新构建，不直接改此文件。单文件版与网站版使用同一套问卷和计分逻辑。

## 2. 修改测试码

在 `config.js` 修改 `accessCode`，同时更新 README 和买家指引中的码。提交到 main，等待 Actions 显示绿色成功后生效。前后空格会被忽略，字母不区分大小写。

每次打开或刷新都会要求输入测试码；入口通过状态仅保留在当前页面内存，不写入本地存储。旧版保存的 unlocked:true 也会在读取时被清除，答题进度和报告保留。换码后用户下次重新打开或刷新时输入新码即可，不需要变更存储版本；已经打开且验证过的页面可继续本次测试。静态码仍可能被查看或绕过，不具有防分享能力。

## 3. 修改题库与文案

正式短版每维 2 题，1 正向、1 反向，再加 2 道压力与支持情境题。内容库每维保留 4 个候选条目，当前组卷取第 1 和第 4 个。`questions` 每项为 `[题目文字, 触发标签或 null, 是否反向]`。反向题必须写 `true`。

仅修改标点或解释文案不需要变更版本。若修改题意、题序或计分，需要同步递增 `config.js` 的 `version` 和 `storageKey`，以免旧答案被套入新题目。题数或维度结构变更需同步检查计分、进度、存储验证与测试。

不要把这份娱乐问卷包装为经过验证的心理量表；不要宣称准确率、人群百分位或医学诊断效果。

## 4. 重新部署

1. 修改后执行 `npm ci`、`npm test`、`npm run build`。
2. 推送 main，或在 GitHub Actions 手动运行 **Check and deploy Pages**。
3. 等待 build 与 deploy 都成功，再打开真实网址检查。
4. 如果首次发布失败，检查 Settings → Pages 的 Source 是否为 GitHub Actions，并检查 Actions 错误日志。

部署需要仓库的 Pages 和 Actions 可用。网站为纯静态，所有资源使用相对路径，支持 GitHub 仓库子路径。

## 5. 恢复旧版本

在 GitHub 提交历史中找到出问题的提交，使用 `git revert <提交号>` 新增一条撤销提交并推送 main。不要强制重写历史。自动部署完成后检查页面。涉及问卷版本恢复时，仍需考虑用户本地旧记录的兼容性。

## 6. 数据与限制

- 不收集姓名、手机号或答案；不使用分析追踪或在线 AI。
- 昵称、每题选择、阶段位置一并保存；只保存一份进度或最近结果；没有服务器备份或跨设备同步。
- 本地存储受限时，页面会提示并继续提供当次答题功能。
- 图片导出在浏览器内完成，依赖随站点打包。完整报告按段生成，减少超长图片造成的内存问题。
- GitHub Pages 和不同用户的网络状况会影响打开速度；不能承诺在所有应用内浏览器中稳定打开或下载。
- GitHub Pages 有商业用途限制，正式商业运营前需重新评估托管方式：[官方说明](https://docs.github.com/zh/pages/getting-started-with-github-pages/github-pages-limits)。

## 7. 30 题版交互与个性化

点击选项后显示选中态 220 毫秒并自动继续；过渡期间禁止重复点击。第 10、20、30 题进入阶段小结。已经看过的阶段不会因回退修改而反复打断。

昵称要求 1–16 个字符，显示时转义，报告和图片均包含昵称。报告基于主导维度、分数档位、欲望与资源组合、触发因素、两道情境题及实际回答生成；同分但作答不同仍可显示不同依据。相同答案产生相同结果，不使用随机结论。

本版存储版本为 2，不套用旧 56 题版答案。未接入用户行为追踪，不能据此声称完测率已提高。


## 8. 页面与导出维护

报告先显示理解指南，再展示封面与六个内容区块。14 维解读默认折叠，导出时全部展开。完整导出共 14 张：指南、摘要、排行、洞察、触发因素、8 张维度明细、行动建议。页面正文在手机端为 17 像素，桌面为 18 像素；标题、选项和雷达标签单独放大。调整样式后请同时检查手机页面和图片导出。
